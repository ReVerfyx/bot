# 🛴 YAservice — Telegram-бот

Магазин **YAservice** в Telegram на **aiogram 3**, который живёт прямо в **GitHub Actions**
и перезапускает сам себя каждые 6 часов. Данные хранятся в **GitHub Issues**,
оплата — криптой (CryptoBot или перевод на кошелёк), каждый заказ подтверждает
живой оператор.

```
клиент → каталог/ссылка → оплата криптой → проверка оператором
       → активация (номер самоката / скриншот) → выдача → возврат через поддержку
```

## Что умеет

| Раздел | Что происходит |
|---|---|
| 🛴 **Самокаты Яндекс Go** | Тарифы 3 / 7 / 30 дней из `config.yml`, цена и описание правятся текстом |
| 🧩 **Выкуп по Сплиту** | Клиент кидает ссылку на товар → бот вытягивает название и цену → считает комиссию по тарифной сетке → спрашивает ПВЗ или курьера |
| 🛍 **Товары с Яндекса** | Фиксированный каталог позиций (по умолчанию пуст) |
| 💳 **Оплата** | CryptoBot (счёт в ₽, оплата криптой, автопроверка) **и** ручной перевод на USDT TRC-20 / TON / BTC с хешем или скриншотом |
| 🔍 **Проверка человеком** | Ни один заказ не выдаётся автоматически: оператор жмёт «Подтвердить» в админке |
| 🛴 **Активация** | После подтверждения у клиента появляется меню кнопок: прислать номер самоката или скриншот → в ответ приходит текст из `config.yml` |
| 📦 **Склад промокодов** | Коды заливаются через админку, выдаются автоматически при подтверждении оплаты, возвращаются на склад при отказе |
| ↩️ **Возвраты** | Заявка → одобрение оператором → клиент присылает кошелёк → отметка «возврат отправлен» |
| 💬 **Поддержка** | Тикеты с перепиской в обе стороны, каждый тикет — issue в репозитории |
| ⚙️ **Админка** | Заявки, все заказы, обращения, склад, статистика, рассылка, бан/разбан |
| 🕶 **Скрытый админ** | У клиентов нет кнопки админки и никаких упоминаний о ней: вход по `/admin` или кодовому слову, обе точки входа бот стирает из чата |

## Комиссия по Сплиту

Клиент платит **только комиссию сервиса**, размер зависит от цены товара:

| Стоимость товара | Комиссия |
|---|---|
| до 60 000 ₽ | 2 000 ₽ |
| 60 001 – 150 000 ₽ | 5 000 ₽ |
| выше 150 000 ₽ | заявка отклоняется, клиент идёт в поддержку |

Сетка меняется в `config.yml → split.tiers`, лимит — в `split.max_price`.

## Установка

👉 **Пошаговая инструкция «где что взять» — [SETUP.md](SETUP.md).** Ниже краткая версия.

### 1. Репозиторий

Репозиторий должен быть **приватным** — в issues лежат заказы, адреса доставки
и промокоды. ✅ Уже сделано.

### 2. Секреты

`Settings → Secrets and variables → Actions → New repository secret`:

| Секрет | Обязателен | Что это |
|---|---|---|
| `BOT_TOKEN` | ✅ | Токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | ✅ | Твой Telegram ID (узнать: [@userinfobot](https://t.me/userinfobot)), несколько — через запятую. **В `config.yml` не вписывать** |
| `ADMIN_SECRET` | — | Кодовое слово для тихого входа в админку |
| `ADMIN_CHAT_ID` | — | ID группы для заявок. Добавь бота в группу админом и возьми ID (начинается с `-100`) |
| `CRYPTOBOT_TOKEN` | — | Токен [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → Create App. Без него останется только ручная оплата |
| `GH_PAT` | — | Classic PAT со скоупом `repo` + `workflow`. Нужен для мгновенного самоперезапуска (см. ниже) |
| `GH_STORE_TOKEN` | — | Обычно не нужен: по умолчанию берётся встроенный `GITHUB_TOKEN` |

### 3. Настройка магазина

Правится **только `config.yml`**, код трогать не нужно:

* `brand` — название, валюта, контакт поддержки, ссылки на канал и отзывы;
* `scooters.items` — тарифы: цена, срок, описание и **`instructions`** — текст, который придёт клиенту после отправки номера самоката или скриншота;
* `split` — лимиты, тарифная сетка комиссии, способы доставки, разрешённые домены;
* `payment.manual.wallets` — **замени адреса кошельков на свои**;
* `texts` — все реплики бота;
* `decor` — эмодзи и стикеры (`file_id` стикера даёт [@RawDataBot](https://t.me/RawDataBot)).

Премиум-эмодзи: положи `custom_emoji_id` в `decor.custom_emoji` — они подставятся
в тексты сообщений. В кнопках Telegram премиум-эмодзи не поддерживает, там
показываются обычные из `decor.emoji`.

### 4. Запуск

`Actions → 🤖 Telegram bot → Run workflow`. Дальше бот поднимается сам.

## Как работает самоперезапуск

* `cron: "0 */6 * * *"` — новая смена каждые 6 часов;
* `concurrency: cancel-in-progress` — свежий запуск гасит предыдущий, поэтому Telegram
  никогда не отдаёт `409 Conflict` на long polling;
* `RUN_DURATION_SECONDS=20700` — через 5 ч 45 мин бот сам гасит polling и корректно
  закрывает сессии (лимит job'а в Actions — 6 часов);
* последний шаг воркфлоу дёргает `workflow_dispatch` через `GH_PAT` — новая смена
  стартует сразу, не дожидаясь cron. Без `GH_PAT` шаг пропускается, и цикл держится
  на одном только cron (возможен простой до нескольких минут).

⚠️ **Расписание работает только в ветке по умолчанию.** Пока код лежит в фиче-ветке,
запускай через `Run workflow` вручную. И помни: GitHub отключает cron в репозиториях
без активности 60 дней — любой коммит снимает паузу.

## Хранилище на GitHub Issues

| Что | Где лежит |
|---|---|
| Заказ | Отдельный issue с меткой `order` + `status:*`, внутри таблица для человека и JSON для бота, в комментариях — история событий |
| Обращение | Issue с меткой `ticket` и перепиской |
| Пользователи | Закрытые issue `[db] users-0…15` (шардинг по 16 документам) |
| Склад кодов | Закрытый issue `[db] stock` |

Заказы можно смотреть и фильтровать прямо во вкладке Issues:
`label:order label:status:awaiting_check`.

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # впиши BOT_TOKEN и ADMIN_IDS
python -m bot             # без GH_STORE_TOKEN данные лягут в ./.data
```

## Тесты

```bash
BOT_TOKEN=1:test python -m tests.check_config      # тексты, каталог, тарифы
BOT_TOKEN=1:test python -m tests.check_callbacks   # каждая кнопка имеет хендлер
BOT_TOKEN=1:test python -m tests.smoke             # заказы, склад, возвраты, сплит
```

Те же проверки гоняет workflow `✅ Проверка` на каждый push.

## Структура

```
bot/
├── main.py            запуск, таймер смены, graceful shutdown
├── config.py          config.yml + .env, рендер текстов, тарифы
├── ui.py              все клавиатуры
├── common.py          показ экранов, уведомления админам, выдача после оплаты
├── middlewares.py     регистрация юзера, бан-лист, техработы, антифлуд
├── states.py          FSM
├── handlers/          menu · orders · payment · activation · split · support · admin · fallback
├── services/          cryptobot · rates · split_parser
└── storage/           models · backends (GitHub Issues / файлы) · repository
```

## Правовая заметка

Сервис не связан с ООО «Яндекс» и не является его официальным представителем.
Перед запуском проверь, что твоя схема продаж не нарушает пользовательское
соглашение Яндекс Go и законодательство твоей юрисдикции — за содержимое
каталога и исполнение заказов отвечает владелец бота.
